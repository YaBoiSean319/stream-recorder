## What to build

Configure the application name and shared colors in Settings while each browser independently follows System, Light, or Dark.

Include applicable persistent state, API, GUI, documentation, and observable tests as one complete slice. Follow the parent specification and glossary; do not close or modify the parent issue.

## Acceptance criteria

- [ ] Fresh installs use neutral grayscale light/dark palettes and System theme; preserve the established main layout and distinct status indicators.
- [ ] Administrators edit shared app name and accent/background/surface/text colors with equivalent validated RGB, hex, and picker controls; all views/browser titles reflect saved identity.
- [ ] Preview unsaved changes, warn about poor contrast, and reset branding only without changing sources, authentication, connections, or recordings.
- [ ] Store shared branding persistently; browser theme choices remain isolated, track live system changes, and preserve valid existing theme selections across updates.
- [ ] Migrate existing appearance settings without permitting an arbitrary browser's former accent preference to overwrite global branding.
- [ ] Provide versioned backend operations and preserve existing access behavior; HTTP/restart/browser tests demonstrate settings, cross-browser isolation, reset scope, desktop/mobile usability, and invalid-value handling.
