## What to build

Manage selective automation permissions, optional key expiry, and machine-request protection from Settings.

Include applicable persistent state, API, GUI, documentation, and observable tests as one complete slice. Follow the parent specification and glossary; do not close or modify the parent issue.

## Acceptance criteria

- [ ] Administrators create labeled keys with selectable operation permissions and optional expiry, list non-secret metadata and last-used time, and revoke keys immediately.
- [ ] Display key material once; persist nonrecoverable verifiers and migrate existing operator/admin keys to equivalent permissions without breaking them.
- [ ] Require API key is a separate persistent setting, off by default and independent of browser-login authentication.
- [ ] Keep GUI session/CSRF paths usable; ensure a documented recovery/key-management path before enabling restrictions, and never fall back from a supplied invalid/expired/revoked key.
- [ ] Apply equivalent permissions to versioned and compatibility routes, including future branding/upload/webhook actions; Operators cannot manage shared settings or delete recordings.
- [ ] HTTP/browser/restart tests cover selectable permissions, expiry/revocation/last use, both auth modes, existing-key upgrade, no secret readback, and denial without side effects.
