# Draft 2: Persistent light/dark logos and favicon customization

**Status:** Draft pending breakdown approval; not yet a published implementation issue.

## Parent

Specification: #21 — https://github.com/YaBoiSean319/stream-recorder/issues/21

## What to build

Upload branding assets in Settings and see the appropriate logo and favicon throughout the app and login screen.

Include applicable persistent state, API, GUI, documentation, and observable tests as one complete slice. Follow the parent specification and glossary; do not close or modify the parent issue.

## Acceptance criteria

- [ ] Support separate light/dark logos and one favicon, with preview, replacement, clearing, and reset integrated into shared branding.
- [ ] Validate documented supported types/limits and decoded content; reject unsafe active content and malformed uploads without losing the previous asset.
- [ ] Store assets on durable storage and serve them through presentation-only access without exposing credentials or unrelated settings before login.
- [ ] Invalidate asset caches appropriately after replacement/reset; select the logo for the effective theme.
- [ ] Expose asset upload/read/replace/delete operations via /api/v1 with Administrator mutation controls.
- [ ] HTTP/browser/restart tests verify assets across app/login views, theme changes, unauthorized mutations, reset behavior, and container replacement.
