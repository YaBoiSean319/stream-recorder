# Draft 8: Reliable manual YouTube uploads and copyable video links

**Status:** Draft pending breakdown approval; not yet a published implementation issue.

## Parent

Specification: #21 — https://github.com/YaBoiSean319/stream-recorder/issues/21

## What to build

Upload completed recordings from the GUI/API through a durable one-at-a-time queue with progress, recovery, retry/cancel, and storage protection.

Include applicable persistent state, API, GUI, documentation, and observable tests as one complete slice. Follow the parent specification and glossary; do not close or modify the parent issue.

## Acceptance criteria

- [ ] Operators/Admins upload finalized playable media with title/description/visibility/tags/category/explicit audience/notification controls; default Unlisted and notifications off, and require an audience choice.
- [ ] Snapshot resolved metadata at enqueue; later recording renames do not change queued metadata or remote videos.
- [ ] Persist one-active-upload queue, progress/attempt/errors/channel binding/resume information and known video identity; display copyable links and keep local recordings.
- [ ] Support retry, cancel, explicit re-upload/requeue, and failed-job protection release through GUI and /api/v1; use caller-scoped idempotency for enqueue and prevent accidental duplicate remote uploads.
- [ ] Bound retries for temporary failures, report permanent/uncertain outcomes clearly, and recover/resume after restart without blindly starting another remote video.
- [ ] Protect queued/active/failed-job media independently of pinning; block queued/active deliberate deletion and refuse new capture if protected media prevents reclamation, while preserving safe-stop behavior.
- [ ] Cancellation never deletes an already-created video and preserves known links; disconnect pauses pending work, same-channel reconnect resumes eligible work, and different-channel reconnect requires explicit requeue.
- [ ] External upload fixture, HTTP/media/browser/restart tests cover metadata, audience, defaults, progress/link copy, one-at-a-time behavior, retry/resume, idempotency, ambiguity, cancellation/deletion races, retention capacity, pinning, multiple jobs, channel replacement, and local-media retention.
