## Parent

Specification: #21 — https://github.com/YaBoiSean319/stream-recorder/issues/21

## What to build

Configure event destinations in Settings and receive signed recording/upload notifications with inspectable retry status.

Include applicable persistent state, API, GUI, documentation, and observable tests as one complete slice. Follow the parent specification and glossary; do not close or modify the parent issue.

## Acceptance criteria

- [ ] Administrators configure destinations, event selection, signing credentials, and delivery status through GUI and /api/v1; normal reads never return reusable signing secrets.
- [ ] Emit recording completion/failure and upload-result events with stable event IDs, useful record/job/video references, and safe payloads without credentials or sensitive source URLs.
- [ ] Persist deliveries and retry temporary failures with bounded backoff across restarts; document receiver deduplication and polling alternatives.
- [ ] Validate receiver URLs and bound timeouts/resources; do not forward signing/auth material to another origin through redirects.
- [ ] Deliveries and webhook management enforce the operation-permission model; slow/failing receivers cannot block capture or upload completion.
- [ ] Local receiver/provider HTTP and restart tests verify signatures, payloads, event IDs, retries, failure visibility, URL/redirect handling, permission denial, and no secret leakage.
- [ ] Provide signature-verification and Power Automate/n8n receiver examples using placeholders.
