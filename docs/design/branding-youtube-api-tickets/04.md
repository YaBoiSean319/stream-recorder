# #25: Editable recording titles and download filenames

**Status:** ready-for-agent

**Issue:** https://github.com/YaBoiSean319/stream-recorder/issues/25

## Parent

Specification: #21 — https://github.com/YaBoiSean319/stream-recorder/issues/21

## What to build

Name a recording at start or rename it afterward through the GUI/API without breaking its stable identity.

Include applicable persistent state, API, GUI, documentation, and observable tests as one complete slice. Follow the parent specification and glossary; do not close or modify the parent issue.

## Acceptance criteria

- [ ] Optional start title and later rename are available to Operators and Administrators, with durable storage and clear validation.
- [ ] Visible list/detail titles and downloaded filenames reflect changes; duplicate titles are allowed.
- [ ] Sanitize filenames and Content-Disposition safely; names cannot change media paths, recording IDs, original timestamps, pin state, or retention ordering.
- [ ] Give legacy unnamed recordings a useful start-time-based fallback without rewriting capture history.
- [ ] Expose matching /api/v1 operations and compatible behavior on legacy routes; rename does not require YouTube connectivity.
- [ ] HTTP/media/browser/restart tests verify rename/download, Unicode/unsafe input, duplicates, stable IDs/dates, permissions, and playable media.
