Publish versioned images and verify deployment

## Parent

Project specification: #1

## What to build

Publish reproducible versioned Docker images to GHCR and deliver verified deployment/update instructions, documented API examples for externally managed Power Automate scheduling, and Cloudflare Access boundary guidance.

Implement this as an end-to-end slice, including persistent state, API, interface, and observable tests where applicable. Parent specification #1 governs the confirmed requirements; do not close or edit it.

## Acceptance criteria

- [ ] GitHub Actions builds and publishes documented versioned GHCR image tags; Compose can deploy a published image without a local build.
- [ ] Document installation, persistent volumes, required permissions, settings/defaults, source URL, storage cap, naming timezone, and image update/rollback procedures.
- [ ] Document that all app access must traverse operator-managed Cloudflare Access, with browser Entra policies and a service-token policy for API automation; do not add built-in login or API keys.
- [ ] Provide API examples for start with optional duration, status polling, targeted retry-safe stop, list/download/delete, pin/unpin, and settings; explain calendar scheduling is external.
- [ ] End-to-end Docker checks exercise preview, capture, processing, downloads, duration, source changes, interruption/recovery, deletion/pins, and storage cleanup using deterministic fixtures.
- [ ] Verify persistent state/media survive published-image replacement and that combined recovery, conversion, and storage behavior remains safe under failures.
- [ ] Document observed HLS timing limits, gaps during outages, recoverable failures, and the impossibility of reconstructing unavailable footage.
- [ ] Keep service tokens and deployment secrets out of the public repository. Tests validate the application boundary; actual Cloudflare/Entra and calendar provisioning remain the operator's responsibility.
