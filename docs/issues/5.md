Reconnect after stream interruptions

## Parent

Project specification: #1

## What to build

Keep the requested session alive across transient HLS outages, preserve footage captured before the outage, reconnect automatically, and produce one final recording with visible interruption details.

Implement this as an end-to-end slice, including persistent state, API, interface, and observable tests where applicable. Parent specification #1 governs the confirmed requirements; do not close or edit it.

## Acceptance criteria

- [ ] Source loss triggers bounded individual connection attempts and continuing retries until operator stop, original timed deadline, or a later storage stop condition.
- [ ] UI and API expose reconnecting state and interruption details; never claim missing footage was captured.
- [ ] Footage before and after reconnection is retained and finalized into one playable MP4 for a compatible fixture; session ID, start timestamp, source, and deadline remain unchanged.
- [ ] Explicit stop works during an outage; duration expiry also stops retries and finalizes existing footage without extending the deadline.
- [ ] Reconnect attempts never admit another session or spawn uncontrolled duplicate capture processes.
- [ ] Deterministic local-fixture tests interrupt and restore the source, inspect resulting media, and cover stop and deadline expiry while disconnected.
