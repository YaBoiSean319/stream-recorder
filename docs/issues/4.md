Manage and pin recordings

## Parent

Project specification: #1

## What to build

Let users deliberately delete recordings and pin important completed footage through the recordings interface and API, with persistent pins and safe deletion semantics.

Implement this as an end-to-end slice, including persistent state, API, interface, and observable tests where applicable. Parent specification #1 governs the confirmed requirements; do not close or edit it.

## Acceptance criteria

- [ ] Recordings list and API expose pin state and support pin/unpin; pin state persists across container replacement.
- [ ] UI requires confirmation for manual deletion. API deletion uses an explicit recording ID and reports unknown or in-use items clearly.
- [ ] Delete removes the selected completed recording's media and metadata consistently; no unrelated recording is removed.
- [ ] Active capture and media being processed cannot be deleted by recording-management operations.
- [ ] Pinning protects against future automatic eviction but does not prevent an explicitly confirmed manual deletion.
- [ ] Observable tests cover download/list consistency after deletion, persistent pin/unpin, unknown IDs, and refusal to delete in-use media; browser tests verify confirmation.
