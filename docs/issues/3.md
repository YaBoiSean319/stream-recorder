## What to build

Allow operators to edit the source and request bounded recordings in the UI or API. Make controls reliable for later Power Automate calendar calls.

Implement this as an end-to-end slice, including persistent state, API, interface, and observable tests where applicable. Parent specification #1 governs the confirmed requirements; do not close or edit it.

## Acceptance criteria

- [ ] UI and API read/update the direct stream URL, persist it across replacement, and validate malformed inputs with clear errors.
- [ ] Each admitted session snapshots its source: editing settings during capture affects only the next session.
- [ ] Both UI and API accept an optional positive duration; omitting duration creates a manual session.
- [ ] Persist original start and absolute end time. Timed sessions stop and finalize at their original wall-clock deadline.
- [ ] Stop is retry-safe and supports targeting a recording ID; stale or repeated calls cannot stop an unrelated later session.
- [ ] Document request/response contracts, units, IDs, busy responses, invalid inputs, and status polling for automation.
- [ ] Acceptance tests exercise source changes during capture, optional duration, invalid duration, repeated stop, and stale targeted stop; UI smoke tests cover settings and duration.
