Enforce storage limits with automatic cleanup

## Parent

Project specification: #1

## What to build

Display storage usage, configure a cap over recorder media, automatically reclaim oldest unpinned completed recordings, and stop safely when there is insufficient space to continue.

Implement this as an end-to-end slice, including persistent state, API, interface, and observable tests where applicable. Parent specification #1 governs the confirmed requirements; do not close or edit it.

## Acceptance criteria

- [ ] UI and API expose filesystem capacity/free space, recorder-media usage, and a persistent editable storage cap with input validation.
- [ ] Usage accounts for completed media, active capture, and temporary conversion artifacts. Capacity checks account for conversion growth and actual free disk space.
- [ ] Proactive cleanup deletes oldest unpinned completed recordings in original-start order and updates the recordings list consistently.
- [ ] Never automatically evict pinned recordings, active capture, or media being processed; coordinate cleanup with recording admission and finalization.
- [ ] If no eligible media can free enough space, refuse unsafe starts or safely stop ongoing capture and expose a storage error, preserving captured media as available space permits.
- [ ] Do not claim a final MP4 will exist when finalization lacks space; show recoverable failure rather than deleting protected footage.
- [ ] Acceptance tests use small isolated caps and controlled low-space conditions, verify eviction order and pin protection, include temporary media in accounting, and cover cleanup during capture/processing.
- [ ] Document cap units/default, cleanup headroom, and distinction between the media cap and underlying disk capacity.
