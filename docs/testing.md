# Testing

Run `python -m unittest discover -s tests -v` from the checkout with Python 3.12+, aiohttp, FFmpeg and FFprobe installed. Acceptance tests start a private recorder process and a real-time local HLS source, each on a dynamically selected loopback port. Their temporary persistent data and generated media are isolated from operator storage. No public stream or identity provider is required.

The acceptance seam is the HTTP API and completed MP4 download. FFprobe verifies audio/video tracks and duration; FFmpeg fully decodes downloaded output. Killing and restarting the application against the same data directory exercises persisted recovery through public API state. Fixture HTTP outages represent unavailable footage, not recoverable replay.

Docker is unavailable in the implementation environment. Local application tests do not establish that a Docker image or Compose deployment works. The CI workflow must build and smoke-test the image before publication; operators must verify persistent mounts and their Cloudflare Access policy in deployment.

The browser test is opt-in with `RUN_BROWSER_TESTS=1`. Install Playwright and its Chromium browser first, then provide `NODE_PATH` (or `CODEX_PRIMARY_RUNTIME_NODE_MODULES`) pointing at the installed Node modules. `CHROMIUM_PATH` optionally selects a browser executable. It tests actual live preview playback, browser closure during recording, controls, downloads, pinning and delete/cancel confirmation. Local browser installation was blocked by the network; this test is supplied for CI and is not claimed as locally passed.

`tests/test_viewers.py` exercises the versioned HTTP seam for empty defaults, independent player configuration, one-time key/snippet delivery, disabled versus healthy zero, origin/key/payload denial, scoped permissions, deduplicated tabs, per-tab stop, key revocation, and 90-second expiry. The opt-in browser acceptance calls `tests/viewer-tracking.cjs` against the local HLS fixture, so actual media progression, same-browser multiple tabs, pause, stall, and revocation are observed without contacting the example public player. Run the expiry case with the full suite; it waits the configured 90-second grace period. Gateway behavior itself remains a deployment check.

Settings coverage uses the same public HTTP and browser boundaries: fresh empty-source admission, explicit source clearing and restart, source changes during capture, and pre-upgrade settings fixtures that retain source, storage cap, pinned recording history, and playable media after default filling. Browser coverage navigates to Settings from the empty state, configures Source and Storage, returns to Recorder, and then exercises capture.

Appearance coverage in `tests/appearance.cjs` uses Settings controls and observed browser state for theme changes, shared branding, reload persistence, isolated browser preferences, device System changes, invalid-preference fallback, keyboard focus, and mobile navigation/overflow. It runs as part of browser smoke. `tests/test_branding.py` checks public branding, administration, persistence, reset scope, and invalid values over HTTP. Browser cases require Chromium.

Asset coverage in `tests/test_branding.py` checks decoded PNG upload, replacement, public image reads, restart preservation with the same persistent data directory, invalid/active/trailing/oversized uploads retaining the prior asset, access controls, per-slot clearing, and branding-only reset. `tests/appearance.cjs` previews, saves, selects the effective light/dark logo, verifies the favicon and reload, and checks discard/reset. Browser smoke also verifies the uploaded dark logo on the sign-in screen. The same persisted directory used in the container replacement workflow carries the SQLite branding manifest and `branding-assets/` files through replacement.

SSO button coverage in `tests/test_branding.py` checks the public default, validated administrator changes, persisted label and independent colors, icon upload/restart/reset, and anonymous write denial. Browser smoke configures the button, verifies the anonymous label/icon and light/dark colors on a narrow screen, activates it by keyboard to exercise a failed provider path, and then signs in through the local recovery form. `tests/test_oidc.py` exercises signed provider role assignment and failed token validation through the same OIDC endpoint.

Failure coverage uses external process fixtures: a temporary FFmpeg command shim rejects conversion while real capture continues; an optional compiled `LD_PRELOAD` fixture reports zero available filesystem blocks. The latter verifies public API handling of OS capacity, without filling the host disk. It requires a C compiler and is skipped when none exists. These controlled failures do not substitute for physical disk-failure testing.

## Combined upgrade review

`test_combined_access_and_protected_capture_survive_replacement` configures a bearer/header-protected local HLS source, local recovery administrator, enabled authentication, administrator/operator keys, and OIDC group mappings. It kills and replaces the recorder process against the same isolated data directory. The public API must retain masked settings, deny anonymous preview and operator configuration/deletion, permit protected preview/capture/download, accept local recovery login, and immediately reject a revoked key. OIDC protocol validation and signed role assignment use the separate local-provider fixture; the combined restart test deliberately does not contact an external provider.

`test_upgrade_fills_missing_settings_without_replacing_legacy_source` supplies a historical two-field settings fixture, including the formerly bundled saved URL. Constructing historical input is the only database fixture setup; all preservation assertions use the public API and playable media download. The old URL is preserved as historical test input, never a new-install default or deployment example.

`test_branding_auth_automatic_queue_and_webhook_survive_replacement` exercises the combined feature state across a recorder process replacement using the same isolated data directory. It captures and pins playable footage from a protected local source, saves shared branding and an image asset, OIDC mappings and API keys, automatic-upload defaults and a channel-bound paused job, a persisted recording-start idempotency key, and a pending signed webhook delivery. The test verifies that the upload remains paused and protects the local recording while the failed webhook attempt is retried after restart with the same event ID. It also verifies source and OIDC secret masking, saved channel/client configuration, and unchanged upload metadata through the public API. Its fixture writes the local YouTube connection directly into SQLite so no real Google credentials or upload endpoint are used; the queued job is paused before any provider request.

For the combined branding, queue, and webhook replacement test, run:

```sh
python -m unittest tests.test_upgrade_integration -v
```

CI runs HTTP/media/browser checks before image publication, repeats server acceptance inside the built image, and replaces a container with the same named volume. `browser-review` contains screenshots from isolated fixtures for visual review, uploaded even if browser checks fail. Screenshots show test configuration only, not operator deployment data. A green local server test is not evidence that browser or container checks passed: reviewers must inspect the actual workflow results and artifacts. No merge or deployment is part of verification.

For a focused restart check, run:

```sh
python -m unittest tests.test_acceptance.RecorderAcceptance.test_combined_access_and_protected_capture_survive_replacement -v
```

For browser evidence locally, set `BROWSER_ARTIFACT_DIR` to a scratch directory alongside `RUN_BROWSER_TESTS=1`; screenshots are optional and do not alter the browser assertions. Missing browser binaries are a skipped check, not a pass.

Validation evidence for the combined upgrade slice: full `python -m unittest discover -s tests -v` passed locally (107 tests, one browser test skipped). The combined test covers protected-source capture, playable download, automatic queue protection, idempotent admission, persisted webhook retry, branding asset, authentication, analytics configuration/history/rollups, and process replacement. Existing tests cover restart probing of YouTube resumable sessions without a second initiation, branding assets, valid browser theme preferences, and media recovery. Browser execution is not claimed: Playwright is installed but its Chromium binary is not. Docker is unavailable locally; actual image build, container replacement and screenshot artifacts remain required CI checks, not locally verified results.

Container capture compatibility: the public playable-download acceptance was reproduced against official FFmpeg 7.1.3 while keeping source generation and output verification on host FFmpeg 6.1.1. Before the fix, opaque relay segment URLs failed `allowed_segment_extensions` and produced no footage; after the fix the same acceptance passed on both versions. FFmpeg reads only the private provenance-bound relay, with HTTP/TCP/crypto protocols and HLS/TS/MP4/AAC/MP3/WebVTT demuxers allowed. Newer filename matching is disabled only when the installed HLS demuxer advertises it. Docker image acceptance remains a separate required CI check.

Additional public capture/download acceptance covers extensionless signed playlist and segment endpoints plus AES-128 HLS keys. Both cases passed against host FFmpeg 6.1.1 and the isolated official FFmpeg 7.1.3 capture binary, preserving encrypted-media support with the restricted transport list.

`tests/test_viewer_history.py` verifies the versioned history HTTP seam for persistent zero samples, active concurrent counts, weighted average/viewer-hours, partial and unavailable coverage, bounded/resolution validation, and scoped-key read/manage boundaries. The opt-in browser acceptance calls `tests/viewer-history.cjs` to exercise historical navigation, peak/average controls, drag selection/reset, keyboard access, and mobile layout alongside the external-player fixture.

`tests/test_viewer_analytics.py` verifies public history responses for spring-forward local-day coverage, multi-date heatmap periods, fall-back duplicate-hour separation, actual Recording windows, active-session bounds, and scoped read authorization. Browser acceptance in `tests/viewer-history.cjs` checks keyboard heatmap selection and single-period drilldown, while `tests/browser-smoke.cjs` checks active and finalized Recording analytics navigation with timezone/configuration context. Playwright browser execution requires a locally installed Chromium binary.

Retention and player-configuration coverage in `tests/test_viewer_history.py` verifies the public Administrator settings contract and invalid-policy atomicity, then seeds deterministic old samples in the persistent database and observes hourly weighted averages, peaks, coverage, viewer-hours, partial-hour omission, repeated collector passes, and process replacement through the history API. It also checks that timezone-only edits preserve configuration identity and that a stale player key cannot report into the current cohort. Rollups use whole UTC hours; a query that selects only part of an old hour leaves that bucket unknown and returns `partial_rollup_hours_excluded` rather than estimating its sub-hour contents.

The final analytics upgrade acceptance in `tests/test_upgrade_integration.py` combines analytics with protected source credentials, OIDC/local recovery and scoped keys, branding assets, pinned playable recordings, automatic YouTube upload state, and signed webhook retry across a recorder process replacement. It confirms two player configuration identities remain queryable, an old hourly rollup stays associated with its former player, current playback presence persists, the read-only key can query but cannot manage settings, source/tracking secrets remain masked, and collector health is distinct from last player contact. `tests/test_viewers.py` asserts the 60-report/IP/minute limit returns 429 and payloads over 4 KiB return 413 without creating presence. The container replacement job also configures analytics, accepts one valid report, replaces the image against the same named volume, and checks configuration identity, retention defaults, secret non-readback, and live presence.

`tests/viewer-tracking.cjs` additionally checks muted and background-tab playback, page-level live counter refresh, progress-based reporting, pause, stall, end, multi-tab deduplication and key rotation. These cases run only when the browser acceptance job has Playwright and Chromium installed; the actual run and screenshots are retained as the `browser-review` artifact. Local runs in environments without Chromium or Docker must report those checks as unavailable, not passed.
